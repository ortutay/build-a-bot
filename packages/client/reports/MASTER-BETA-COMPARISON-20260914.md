**Queue diagnosis**

Both branches construct the same queue in `Compiler.ts`:

```ts
new PQueue({ concurrency: 50, intervalCap: 5, interval: 1000, strict: true });
```

`concurrency` is the maximum unfinished tasks; `intervalCap` permits only five starts in a rolling second. `queued` and `running` describe that one compiled script's shared queue, not the number of Node worker threads or all scripts. The log records the count at the instant a task starts. Fast tasks can finish between allowed starts, leaving a large backlog with `running=1`.

A live master Pokémon sample had **142 starts in 26.258 seconds, 141 fetch hits, no fetch misses, and 95 starts with `running=1`**. Its remaining queue was still around 900 tasks. A concurrent beta sample had **622 starts over 122.428 seconds**, with 615 fetch misses; it also usually showed only one to three running tasks. This reproduces the reported symptom in both versions.

| Controlled benchmark: 30 tasks, concurrency 50 |  Elapsed | Peak running |
| ---------------------------------------------- | -------: | -----------: |
| 1 ms tasks, existing 5/sec limit               | 5,009 ms |            5 |
| 150 ms tasks, existing 5/sec limit             | 5,157 ms |            5 |
| 150 ms tasks, no launch-rate limit             |   151 ms |           30 |

The benchmark is synthetic; it does not recommend sending unlimited requests to a live site. It isolates the rate limiter from remote latency and generation time.

At one queue task per Pokémon, 1,025 detail pages require about **204 seconds just to launch**, even when cached. Build seed validation runs the national listing, then the client's explicit sync runs it again. The all-proxy master rerun confirmed that separately queueing document reads doubles full national sync to **410.61 seconds**, consuming additional slots without additional network requests.

The useful change is to rate-limit actual network operations after cache lookup, preferably by host/proxy, while retaining a concurrency cap for queued extraction tasks. Keep local document reads outside the request limiter. A smaller first step is configurable rate limits plus logs for the configured limits, completed tasks/sec, cache hits and rate-limited state. Raising `concurrency: 50` alone does not address this problem. Neither branch currently implements this change. The generation prompt also claims the queue settings already reflect robots.txt, although the implementation uses a fixed global value; that claim should be removed or backed by actual configuration.
